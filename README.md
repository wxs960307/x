# xreply · 猫大推特回帖助手

一个跑在 Chrome 里的 X（Twitter）回帖助手。给它一个 x.com 标签页和一段人设，它会自己翻时间线、挑帖、写回复，然后按真人的节奏发出去。

不是「每 5 分钟回一条」那种机器人。整套设计只围绕一件事：**看起来像一个人，而不是一个进程。**

![面板](panel.png)

---

## 它做什么

| 动作 | 频率 | 说明 |
|---|---|---|
| **回帖** | 一天上限 60 条（是上限，不是目标） | 翻指定 tab，让模型判断哪几条值得接，只接那几条 |
| **顺手关注** | 一天最多 40 个 | 回帖时如果这个作者也够格，顺手关注；关注和回帖是两套独立判断 |
| **偶尔转推** | 每天现抽 0~2 个 | 内容够硬但没话说时，让粉丝自己去看 |
| **偶尔引用** | 每天现抽 0~3 个 | 内容够硬**且**有一句别人说不出的话时，自己发一条 |
| **什么都不做** | — | 一批里一条都不值得回，就空着翻下一批。这是正常状态，不是失败 |

## 它刻意不做什么

- 不喊单、不给点位、不劝买卖（模型层和机械闸门层各拦一次）
- 不批量关注、不刷量、不追求「每条都回」
- 引用正文里不用 `#` 话题标签（硬拦，不看模型心情）
- 不提合约、杠杆、爆仓

## 为什么它看起来像人

### 1. 一段一段刷，不是均匀铺开

真人不是每 5 分钟回一条。他是坐下来刷一阵，回几条，然后走开。

```
坐下 → 回 4~9 条（条间隔 30~70 秒）→ 走开 15~45 分钟 → 回来再坐下
```

走开多久跟刚坐了多久正相关：坐得久就歇得久。一天下来是**几段密集 + 几段空白**，不是一个均匀的梳子。

### 2. 每条都按内容量花时间

原来有个 bug：09:01:53 看到帖子，09:02:05 就回完了，12 秒。真人不可能——光是打完那 32 个字就要 40 秒。

现在四个阶段各自算：

| 阶段 | 依据 |
|---|---|
| 读 | 中文约 10 字/秒（含理解的停顿），最少 5 秒，最多 90 秒 |
| 想 | 10~40 秒随机，看这条有没有值得接的点 |
| 打 | 55 字/分钟 × 1.3（删改、停顿、改主意） |
| 查 | 3~10 秒，发之前扫一眼有没有错字 |

一条 32 字的回复配 60 字的帖子，算下来 70~110 秒，中位 87 秒。

### 3. 三种动作的量级差得很远

```
回帖   几十条/天
关注   几十个/天
转推   一两个/天   ← 差一个数量级
引用   一两个/天   ← 差一个数量级
```

一个币圈号一天转十条，比一条都不转还显眼。

### 4. 配额是每天现抽的，不是固定值

「每天正好 2 个」本身就是规律。所以每天开局现抽一个 `0~N` 的数，**抽到 0 就那天一个都不动**——才有「今天不想转」的人味。

## 引用的质量闸

引用是整个项目里最危险的按钮：它是**你自己发的一条帖**，永久留在主页上，原作者还会收到通知。转推写错了取消就没了，引用写错了删帖也没用（已经被截图了）。

所以引用这条路有三道闸：

1. **模型打分**：`r=3` 引用 / `r=2` 转推 / `r=1` 不动 / `r=0` 垃圾
2. **本地硬门槛**：转推/回复带出来的不要、少于 30 字不要、纯链接不要、抽奖拉群不要、回复数超过 150 的大V帖不要
3. **文字质量闸**：生成完机械检查一遍

质量闸拦这些：

```
· 长度不在 60~280 权重（约 30~140 个汉字）
· 碰红线：看涨 / 看跌 / 目标价 / 止损 / 抄底 / 梭哈 / 上车 / 合约 / 杠杆 / 爆仓 / 强平 / 点位 / 加仓
· 用了 # 话题标签
· 「不是……，而是……」对偶句
· 套话：说白了 / 本质上 / 归根结底 / 值得注意的是 / 总的来说 / 综上 / 由此可见
· 破折号做解释
· 问句收尾（互动钓饵）
· 空话开头：说得好 / 有道理 / 感谢分享 / 确实 / 同意 / 支持 / 学习了 / 受教
· 作文腔开头：「关于……，我认为」
· 复述原帖（出现原帖连续 8 个字）
· 没有实质锚点（数字 / 自己的经历 / 具体标的，一个都没有）
```

不合格就打回重写一次，**两次都不合格就放弃这条**。宁可少发一条，也不发一条 AI 味的永久帖。

提示词里除了这串禁令，还给了一对正反例子——模型对「照着这个语气写」的服从度，比对「别用破折号」高得多。禁令只是兜底。

## 安装

1. 下载或 clone 本仓库
2. Chrome 打开 `chrome://extensions/`
3. 右上角打开「开发者模式」
4. 点「加载已解压的扩展程序」，选 `extension/` 目录
5. 点扩展图标，侧边栏打开面板

需要 Chrome 114+（用到 `sidePanel`）。

## 配置

| 字段 | 说明 |
|---|---|
| API Key | DeepSeek 的 key。默认接口 `https://api.deepseek.com`，换别的 OpenAI 兼容服务商改接口地址就行 |
| 抓哪个 tab | x.com 主页上那个标签的名字，默认「加密」 |
| 每天最多发几条 | 上限，默认 60。**不是目标** |
| 只在几个时间段跑 | 例如 `09:00-12:00, 20:00-23:30`，留空 = 全天 |

高级里还有：每批看几条、一批挑几条回、一次坐下回几条、条间隔、走开多久、关注/转推/引用的日上限和门槛。

**先跑一次「试运行」**——只填框不发，看清楚它写出来的是什么再开真的。

## 架构

纯 Chrome MV3 扩展，没有本地服务。

```
background.js   service worker：状态机、调度、模型调用、质量闸、所有存储
content.js      content script：DOM 操作（翻时间线、找推文、填框、点按钮）
panel.html/js   侧边栏 UI
```

三层之间只有消息，没有共享内存。**所有状态都在 `chrome.storage` 里**，因为 service worker 随时会被杀。

### 为什么用状态机而不是 `await sleep()`

MV3 的 service worker 空闲 30 秒就被终止。一个 `await sleep(90 * 1000)` 写在那里，等于赌这 90 秒内 worker 不会被回收——必输。

所以循环不是「跑一遍」，而是：

```
每次心跳推一格 → 到点了就往前走一步 → 没到点什么都不做
```

`phase`（`fetch / reply / window / away / idle`）+ `nextAt` 存进 storage，配合 `chrome.alarms`（30 秒一次）兜底唤醒。worker 被杀，重启后从 storage 里读回状态，接着跑。

### 为什么页面的 sleep 要发到后台

页面切到后台之后，Chrome 会把 `setTimeout` 压到 1 秒一次，隐藏超过 5 分钟压到 60 秒一次。一条回复里有十几次几百毫秒到几秒的等待，全被拉长就等于停摆。

所以 content script 的 `sleep` 不自己等，发一条 `{type:'nap', ms}` 给 background，由那边计时——service worker 没有可见性概念，不受这套节流影响。

## 踩过的坑

这些都是单测全绿、真跑才炸的，记下来省得下次再踩。

**整页跳转会断消息通道。** `chrome.tabs.sendMessage` 的响应在页面刷新时丢失，任务看起来失败了，但页面上其实已经做完了。所以有 `RESUME_KEY` 接力机制——只支持 `fetch` 和 `reply`。转推和引用**绝不做整页跳**：翻不到就放过，因为重复发一条引用比漏发难看得多。

**`findComposer()` 会摸到时间线顶部那个框。** 那是「有什么新鲜事」，往里面填字就是发一条新推文，不是回复。所以填字前必须确认输入框在弹窗里（引用）或在 `/status/` 页上（回复），否则宁可跳过。

**已经转过的帖子，再点一次「转推」是「取消转推」。** 比不转还糟——粉丝刚看到你转，转头就没了。所以转推前先查 `unretweet` 状态，有就直接报 `already` 退出。

**引用崩在中间，重启后会变成回帖。** 引用要跑六七分钟，worker 中途被杀的话，重启后 `state='引用中'` 不在跳过条件里，会一路落到回帖分支——刚引过的帖子又被回了一条。现在三种动作都写 `inflight{url, at, kind, tmo}`，过期时间按任务自己的超时算（引用 420 秒、转推 200 秒、回帖按字数），不是写死的 130 秒。

**`parseBlocks()` 会在空行处切段。** 回帖取第一段是对的（模型给了几条候选），引用取第一段就是把一句话腰斩——而且它不报错，第一段够长就能过闸。所以引用是 `join('')`。

## 测试

没有浏览器也能跑大部分逻辑。`_test_ext.js` 用 Node 的 `vm` 把 `background.js` 跑起来，喂它假的 `chrome.*` 和假的 `fetch`。

```bash
node _test_ext.js
```

313 条断言，覆盖：去重、失败重试、会话节奏、时间窗、配额抽签、质量闸、崩在引用中间、点了停止、窗口外不引、r=3 退回转推。

`_test_ext.js` 里还包含**静态接线检查**——比如「background 派了 quote 任务，content 必须接得住」。加转推的时候踩过一次：单测用的假页面直接处理 `follow`，绕过了 content.js，所以 `follow` 分支被误删了也没红，真跑起来直接报「未知任务类型」。那之后每种任务类型都有一条静态断言。

UI 用 `.preview/build_demo.js` 生成静态页面，`.preview/probe.js` 注入进去量布局和文案，71 条断言。
